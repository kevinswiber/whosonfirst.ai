# Implementation evidence review

The source reviews were checked on **12 and 13 November 2026 (America/Los_Angeles)**, and extended on 14 November by [the first run of implementation research](research-2026-11-14.md). They cover all 25 published flows. The [evidence records](../../src/data/implementations/records.ts) select 158 implementation entries, 34 attributed deployment accounts and one scoped interoperability observation. This document records the reviews of 12 and 13 November; each later run has its own dated file beside it. The initial pass covered five flows, followed by five more and then the remaining 15. Coding agents performed the source reviews and a separate check of selected claims and publication rules. These records do not assert independent human or operator verification, exhaustive coverage or prevalence.

The review started with the [design and pilot findings](review-and-design.md), the pilot ledger and the site’s flow definitions. It opened product documentation, release announcements and first-party operator accounts. Targeted searches filled gaps in roles and operator evidence. The initial public selection used two or three actionable implementation entries and at most one operator account per flow. The extension broadened those records. The Implementations directory links each reviewed entry to its full record. Further candidates and exclusions remain research context. The resulting records are examples. No new endpoint survey, operational test, independent certification or prevalence measurement took place.

Dates below identify a review, publication or reported event. A page’s update date applies to the document. An operator account can describe a rollout without establishing its date or current status. Adding an existing source to the directory is a change in evidence coverage. An unstated feature stage stays unspecified. Project and publisher wording is preserved at the scope it describes.

## Authorization code with PKCE

- **Accept · Amazon Cognito user pools, authorization server.** AWS documents a public app client using S256 and redeeming the code with the verifier. See _How Amazon Cognito uses PKCE_, steps 6–7. [Using PKCE in authorization code grants](https://docs.aws.amazon.com/cognito/latest/developerguide/using-pkce-in-authorization-code.html)
- **Accept · oauth4webapi, client library.** The project lists code flow with PKCE under _Features_ and v3.x under _Supported Versions_. The support statement applies to the library branch. Feature introduction and publication date are unstated. Native app integration and a specific issuer pairing remain untested. [oauth4webapi README](https://github.com/panva/oauth4webapi/blob/main/README.md#features)
- **Accept · GitHub OAuth Apps and GitHub Apps, authorization server.** The GitHub changelog labeled its S256 support announcement a release on 14 July 2025. The announcement describes verifier enforcement when the client sends a challenge and a historical compatibility exception. It covers user authorization for the named app types. [PKCE support for OAuth and GitHub App authentication](https://github.blog/changelog/2025-07-14-pkce-support-for-oauth-and-github-app-authentication/)

No qualifying operator account was selected. The GitHub announcement’s unnamed compatibility exceptions are rollout context. The pilot’s age-based inference of general availability was excluded.
