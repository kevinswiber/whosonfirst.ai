# Sources read again, 19 November 2026

A run that read again every implementation source with no recorded passage, and recorded one. It started from the source review of 19 November 2026. `npm run sources:changed` flagged most of the implementation sources, and `npm run implementations:check` found all 188 recorded passages. Another 136 sources, on 100 entries, had no quote to check: they came from entries added before 14 November.

Five coding agents each took a group of flows. For each unquoted source, an agent:

- read the page;
- copied the passage that carries the entry’s claim, with the heading it is under;
- read the entry’s role, stage, summary, qualification and limits against the page again.

Each agent checked its passages with the same page rule and text normalization that `npm run implementations:check` uses. No product was tested, no account was created and no protocol endpoint was called.

## What it left

- **Quotes.** All 136 sources now carry a quote and its section. `npm run implementations:check` finds 320 of the 324 passages in the records. It cannot reach the other four from either network that was tried; see “Read in a browser”.
- **Dates.**
  - 98 entries whose unquoted sources were all read again, and still support them, are checked on 19 November.
  - All 25 profiles are reviewed that day.
  - Earlier events are unchanged.
- **Corrections.** Eight entries were corrected from their sources, listed below.
- **Not re-dated.** Two entries keep their earlier dates, because their other sources were read on 14 November and not again: `identity-chain-authgent` and `txn-authgent`.

Quotes are not shown on the site, and no second agent read them. The corrections were confirmed at each source before they were made.

## Corrections to existing entries

- **`exchange-okta`.** Okta’s guide now documents the `act` claim: “The actor claim (act) identifies the service app that requested the token exchange.” An earlier one “is nested under act.act”, and “This delegation chain has a maximum length of five actors.” The request still sends no actor token, so the qualification stands.
- **`oauth-mtls-duende`.**
  - The setup guide shows the certificate used for “authorization code redemption, refresh, and userinfo calls”, which are all calls to IdentityServer.
  - The call to the API is on the proof-of-possession page: “The client must then use the same client certificate to call the APIs.”
  - That page also says the feature is part of the Enterprise (legacy), Standard, Advanced and Custom editions, now the qualification.
- **`authzen-id-partners`.** “The current published release is 0.4.1”, and “the 0.4.2 candidates behave as 0.4.1”. The entry had named 0.4.2 as the released image.
- **`mcp-claude-code`.** The authentication sections still name no MCP revision. A section on client runtimes now says “The v2 runtime is the same code on MCP TypeScript SDK 2.0, which adds MCP protocol revision 2026-07-28”. It also says when Claude Code uses it.
- **`mcp-stripe`.** The page is labeled “Public preview”, now the qualification.
- **`credential-broker-docker`.** “Custom secrets are experimental. Behavior, flags, and the placeholder format may change without notice.”
- **`credential-broker-postman`.** The blog post’s title is now “Enterprises: Stop Handing Out API Keys! (How Postman Ended Credential Sprawl with Passport)”.
- **`url-elicitation-python`.** Its limits are carried by a second page, which is now its second source: the SDK’s [Elicitation](https://py.sdk.modelcontextprotocol.io/handlers/elicitation/) guide says “accept” “means the user agreed to open the URL, not that they finished what's on the other side”, and shows the completion notification as a separate call.

## Read in a browser, and from a second network

- **Four pages refused both networks.** They were developer.ebay.com (both sources of `client-creds-ebay`), www.icabanken.se (`ciba-ica-banken`) and help.openai.com (`web-bot-auth-openai`).
  - They answered with HTTP 403 or a bot challenge from the review’s network. That held for several user agents, Accept headers, HTTP/1.1 and Node’s fetch.
  - From a second network, the site owner’s own computer, they refused both the check’s request and a browser-style one. They were not worked around.
- **Read in the owner’s Chrome.** The owner opened the four pages there the same day, and the text Chrome rendered was read through AppleScript.
  - Each quote was copied from that text, character for character.
  - The check’s own text rule finds each one in it.
  - All four still support their entries:
    - eBay’s guide documents the client credentials grant at its production token endpoint, with the client ID and secret in a Basic header.
    - eBay’s Browse API page requires the Application access token that grant mints.
    - ICA Banken’s item of 31 May 2024 announces the decoupled flow.
    - OpenAI’s article still shows the quoted origin in `Signature-Agent` and a separate key directory.
  - `npm run implementations:check` reports these four as not reached. Reading them again needs a browser.
- **Three GitHub release pages** (`agent-payments-ap2-python`, `biscuit-rust`, `gnap-rafiki`) could not be read from the review’s network.
  - They were read from the owner’s computer the same day, with the check’s own request and text rule, and given quotes.
  - `npm run implementations:check` then found all three from the review’s network as well.
  - AP2’s release says “This is the second release of AP2.” Rafiki’s releases page lists only beta releases, the latest v2.4.2-beta of 29 October 2026.
