# Sources read again, 19 November 2026

A run that read again every implementation source with no recorded passage, and recorded one. It started from the source review of 19 November 2026. `npm run sources:changed` flagged most of the implementation sources, and `npm run implementations:check` found all 188 recorded passages. Another 136 sources, on 100 entries, had no quote to check: they came from entries added before 14 November.

Five coding agents each took a group of flows. For each unquoted source, an agent:

- read the page;
- copied the passage that carries the entry’s claim, with the heading it is under;
- read the entry’s role, stage, summary, qualification and limits against the page again.

Each agent checked its passages with the same page rule and text normalization that `npm run implementations:check` uses. No product was tested, no account was created and no protocol endpoint was called.

## What it left

- **Quotes.** 129 of the 136 sources now carry a quote and its section. `npm run implementations:check` finds all 317 passages in the records.
- **Dates.**
  - 92 entries whose unquoted sources were all read again, and still support them, are checked on 19 November.
  - The 24 profiles that hold them are reviewed that day.
  - Earlier events are unchanged.
- **Corrections.** Seven entries were corrected from their sources, listed below.
- **Not re-dated.** These entries keep their earlier dates:
  - six whose sources include one that could not be reached: `client-creds-ebay`, `ciba-ica-banken`, `web-bot-auth-openai`, `agent-payments-ap2-python`, `biscuit-rust` and `gnap-rafiki`;
  - two whose other sources were read on 14 November and not again: `identity-chain-authgent` and `txn-authgent`.

Quotes are not shown on the site, and no second agent read them. The corrections were confirmed at each source before they were made.

## Corrections to existing entries

- **`exchange-okta`.** Okta’s guide now documents the `act` claim: “The actor claim (act) identifies the service app that requested the token exchange.” An earlier one “is nested under act.act”, and “This delegation chain has a maximum length of five actors.” The request still sends no actor token, so the qualification stands.
- **`oauth-mtls-duende`.**
  - The setup guide shows the certificate used for “authorization code redemption, refresh, and userinfo calls”, which are all calls to IdentityServer.
  - The call to the API is on the proof-of-possession page: “The client must then use the same client certificate to call the APIs.”
  - That page also says the feature is part of the Enterprise (legacy), Standard, Advanced and Custom editions, now the qualification.
- **`authzen-id-partners`.** “The current published release is 0.4.1”, and “the 0.4.2 candidates behave as 0.4.1”. The entry had named 0.4.2 as the released image.
- **`mcp-claude-code`.** The authentication sections still name no MCP revision. A section on client runtimes now says “The v2 runtime is the same code on MCP TypeScript SDK 2.0, which adds MCP protocol revision 2026-07-28”. It also says when Claude Code uses it.
- **`mcp-stripe`.** The page is labeled “Public preview”, now the qualification.
- **`credential-broker-docker`.** “Custom secrets are experimental. Behavior, flags, and the placeholder format may change without notice.”
- **`credential-broker-postman`.** The blog post’s title is now “Enterprises: Stop Handing Out API Keys! (How Postman Ended Credential Sprawl with Passport)”.

## Not reached

- **developer.ebay.com** (both sources of `client-creds-ebay`) and **www.icabanken.se** (`ciba-ica-banken`) answered every request with HTTP 403, their home pages included. The agents tried several user agents, Accept headers and HTTP/1.1, and Node’s fetch.
- **help.openai.com** (`web-bot-auth-openai`) answered with a bot challenge. It was not worked around.
- **Three GitHub release pages** (`agent-payments-ap2-python`, `biscuit-rust`, `gnap-rafiki`) could not be read for their text here.
  - The projects’ changelogs and tags were read through raw.githubusercontent.com and git.
  - They agree with the entries: AP2 has “0.2.0 (2026-04-28)”; biscuit-auth 6.0.0 is tagged on 16 July 2025; Rafiki’s 2.x tags still end in “-beta”.
  - Those copies are not the pages the entries cite, so the entries carry no quote for these sources.
